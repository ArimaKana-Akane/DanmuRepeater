# 第二阶段（同日追加）：meta.json 去依赖 + P1-11 + L2 + L4

## 目标

用户追加要求：① 不依赖 `meta.json` 也能自动更新；② 按自己想法实现 P1-11（原生发送 + L2）
与 L4（多标签唯一发送者）；③ 不做真机回归；④ 多思考更严重的问题。

## 实现

1. **发布元数据自动识别（不再需要 meta.json）**
   - `scripts/build-hybrid.mjs` 新增 `detectRepo()`：`GITHUB_REPOSITORY`（CI）→
     `git remote get-url origin` → `package.json repository` → 最后才回退 `meta.json`。
   - 识别到即注入 `@homepageURL/@updateURL/@downloadURL`；`@version` 改为从 `package.json` 读取。
   - 模拟 CI 验证：`GITHUB_REPOSITORY=... npm run build` 产物头出现三条 URL，产物守卫通过。
2. **P1-11 原生发送（B 站，默认关闭）**
   - `httpJson()`：优先 `GM_xmlhttpRequest`（绕过 CORS、带 cookie），不可用回落 `fetch`；
     新增 `@grant GM_xmlhttpRequest` + `@connect api.bilibili.com / api.live.bilibili.com`。
   - `protocolSend()`：`room_init` 解析真实房间号 → `POST /msg/send`（csrf/csrf_token/
     platform/web_location/Referer/Origin）→ `mapBiliSendCode()` 归一化。
   - 安全策略：未登录/CSRF 缺失/非 B 站 → 回落 DOM；平台明确拒绝或网络异常 →
     `SEND_FAILED` 且**绝不回落**（避免“请求已到达但响应异常”时双发）。
   - UI 新增“发送”下拉（DOM 默认 / 协议直发实验），切换时二次确认；配置键 `sendMode`。
3. **L2 结构化加权**
   - 协议 `uid/nick/ts` 进入 `metaMap`（按最近 500 条裁剪）；`__lgjMetaBoost` 综合
     独立发送者数 + 频次 + 新鲜度，在 `weightedRandomSelect` 里给候选乘 1~1.8（DOM 为 1）。
4. **L4 多标签 leader 选举**
   - `LeaderElection`（hybrid-core.mjs，19 例单测之一）：带过期租约 + 写后回读 +
     `BroadcastChannel` 心跳；`isLeader()` 发送前再校验租约，缩小旧 leader 双发窗口。
   - `runBot` 增加 leader 守卫；`window.__lgjIsLeader`；GM 存储按标签页隔离时退化为
     `tabId` 字典序 + 心跳收敛。
   - B 站 blanc 让位时调用 `__lgjEngineOnStandDown`：停协议/选举并**释放租约**，
     避免主文档占着 leader 让 iframe 实例永久待机。
5. **自审发现并修复的回归**
   - 仅给 `ensureObserverRunning` 加协议守卫不够：`startContainerPolling` 的容器命中分支
     与 body 降级分支仍会在协议接管后重新启动 DOM observer → 双源叠加。已对两处都加守卫。
   - `parseDelimitedList` 若按逗号分隔会拆坏含逗号的正则（`/a,b/`）→ 改为只按换行分隔。

## 更严重的问题（代码无法消除，已在 README 记录）

1. “复读”本身是风控对抗；硬约束只能降风险，不能消除。
2. 协议直发与页面自身 `/msg/send` 的参数/Header 并非完全一致，仍可能被单独标记。
3. 自连 WS ≠ Hook 页面 WS：多一条连接、需要 wbi 签名，隐蔽性不如 patch 页面 `WebSocket`。
4. 只有 B 站有协议源；斗鱼/虎牙/抖音仍靠 DOM 选择器，改版即失效。
5. 多标签 leader 依赖 GM 存储跨标签共享；隔离存储时仍有最多 5s 的收敛窗口。
6. 网络歧义下“宁可不发不可双发”会带来偶发漏发。
